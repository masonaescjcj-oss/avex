# وضعیت واقعی سیستم — چه چیزی کجاست

این فایل برای این نوشته شده که **هیچ‌چیز مهمی فقط داخل یک گفت‌وگو نماند**. هر عددی که
اینجاست از خود سرور خوانده شده، نه از حافظه.

آخرین به‌روزرسانی: ۲۰۲۶-۰۹-۰۴ · کامیت `2d5c5d2`

---

## ۱. چه چیزی روی گیت‌هاب هست

**همهٔ کد و همهٔ مستندات.** ۳۴۰ فایل، همه push شده، هیچ کامیت نرفته‌ای نمانده. برنچ
`claude/avex-pay-setup-cnlasi` همان **برنچ پیش‌فرض** مخزن است، پس چیزی روی شاخهٔ فرعیِ
فراموش‌شده نمانده.

داخلش: API، داشبورد فروشنده، پنل ادمین، صفحهٔ پرداخت، سایت، قرارداد `Forwarder.sol`،
پلاگین ووکامرس، اسکریپت نصب (`deploy/install.sh`)، مایگریشن‌ها، و ~۱۲۰۰ تست.

مستندات: `START.md` (راه‌اندازی، دستور به دستور) · `docs/GO-LIVE-fa.md` (صفر تا صد، با
دلیلِ هر تصمیم) · `docs/ARCHITECTURE.md` · `docs/api.html` (رفرنس API) · همین فایل.

## ۲. چه چیزی روی گیت‌هاب **نیست** — و عمداً نیست

هیچ رمزی در مخزن نیست. این‌ها فقط جای خودشان هستند:

| چیست | کجاست | اگر از دست برود |
|---|---|---|
| `api.env` — رشتهٔ دیتابیس، رمز SMTP، `MEMO_SECRET` | `/etc/avex/api.env` روی سرور (۰۶۰۰، مالک root) | با `sudo bash deploy/install.sh --reconfigure` از نو ساخته می‌شود |
| **کلید تسویه** (کیف پول گس) | `/etc/avex/settlement-key.cred` روی سرور | **قابل بازیابی نیست.** با `systemd-creds` رمزنگاری شده و **فقط روی همان ماشین** باز می‌شود. سرور برود، موجودی گس هم رفته. برای EVM لازم است؛ TRON به آن نیازی ندارد. |
| رمز و کلید 2FA حساب ادمین | فقط در authenticator خودت | با ساختن ادمین دوم و disable کردن اولی جایگزین می‌شود (رمز TOTP قابل reset نیست، فقط قابل رها کردن) |
| کلیدهای API فروشنده‌ها، secret وبهوک‌ها | فقط hash در دیتابیس | یک بار نشان داده می‌شوند؛ گم شد، باید نو ساخت |
| دیتابیس (فروشنده‌ها، فاکتورها، پرداخت‌ها) | Postgres محلی روی همان سرور — `localhost:5432/avex` | **بکاپ ندارد.** بخش ۵ را ببین. |
| متغیرهای Vercel (`AVEX_API_URL`, `AVEX_SITE_URL`) | در پروژهٔ Vercel | با `vercel env add` |
| رکوردهای DNS | در پنل دامنه | — |

## ۳. سرور، همان‌طور که هست

```
Ubuntu 26.04 · systemd 259 · node v22.23.2 (/usr/bin/node)
2.3GB رم آزاد · 46GB از 59GB دیسک آزاد
```

- کد: `/opt/avex` — برنچ `claude/avex-pay-setup-cnlasi`
- سرویس‌ها: `avex-api` و `avex-watcher` (systemd، نه pm2)
- **API روی پورت ۳۰۰۳** است، نه ۳۰۰۰ — پورت ۳۰۰۰ را یکی از پروژه‌های دیگرت گرفته بود و
  نصاب خودش پورت آزاد را انتخاب کرد
- TLS با **nginx** (که ۸۰/۴۴۳ را دارد)، نه Caddy. `api.avexpay.net` → `127.0.0.1:3003`
- دیتابیس: **Postgres محلی**، `localhost:5432/avex` — Supabase در مسیر نیست
- روی همان سرور: `avex-commerce-backend`، `prediction-arena-backend`، `trade-backend` زیر pm2

سه دستور که همیشه به کار می‌آیند:

```bash
sudo bash /opt/avex/deploy/install.sh --report   # چی نصب است، چی اجرا است، دیتابیس جور است؟
sudo bash /opt/avex/deploy/install.sh            # کد جدید بگیر، بساز، مایگریت کن، ری‌استارت کن
journalctl -u avex-watcher -f                    # لاگ زندهٔ واچر
```

`/health` کامیتِ در حال اجرا را می‌گوید. اگر `build` را نشان نداد، پروسه از کد قدیمی است:

```bash
curl -s localhost:3003/health
# {"status":"ok","build":{"commit":"…","branch":"…","built":"…"}}
```

## ۴. Vercel

`avexpay.net` از پروژهٔ `avex-pay` سرو می‌شود. بیلد از خود مخزن:
`npm run build:static` → `deploy/out`. مسیرها: `/` سایت، `/dashboard` داشبورد فروشنده،
`/admin` پنل ادمین، `/pay/:id` صفحهٔ پرداخت، `/docs` رفرنس.

به‌روزرسانی صفحه‌ها: `vercel --prod` از ریشهٔ مخزن. (تغییر در API ربطی به Vercel ندارد و
برعکس.)

## ۵. کارهایی که مانده

به همین ترتیب:

1. **ری‌استارت روی کد جدید** — `curl -s localhost:3003/health` باید `build` داشته باشد.
2. **2FA حساب فروشنده** — تب Security در داشبورد. ۱۰ کد بازیابی را همان‌جا ذخیره کن؛ فقط
   hash نگه می‌داریم.
3. **کیف پول‌های خودت، روی هر زنجیره‌ای که می‌خواهی** (تا ۱۰ تا در هر زنجیره) — کلید دست
   خودت می‌ماند، ما فقط آدرس را نگه می‌داریم. تب Payouts، پنل «Your own wallets».
4. **یک پرداخت واقعی کوچک** — روی TRON یا هر زنجیره‌ای که کیف پول ثبت کرده‌ای. حداقلی ندارد؛
   ۰.۱ USDT هم می‌شود. **همان مبلغ دقیقی
   که فاکتور می‌گوید** را بفرست — سنت آخرش عمداً یکتاست و همان چیزی است که پرداخت را به
   فاکتور وصل می‌کند.
5. **SMTP واقعی** قبل از هر فروشندهٔ واقعی. الان transport کنسول است: لینک تأیید ایمیل فقط
   داخل `journalctl` است، پس فقط خودت می‌توانی حساب بسازی.
6. **بکاپ دیتابیس.** یک `pg_dump` شبانه روی این سرور تنها بکاپی است که وجود دارد و الان
   وجود ندارد:
   ```bash
   sudo -u postgres pg_dump avex | gzip > /root/avex-$(date +%F).sql.gz
   ```
7. **عوض کردن رمزهایی که در چت رفته‌اند** — رمز دیتابیس Supabase پروژهٔ دیگرت و کلیدهای
   API آن، و حساب ادمین AVEX: ادمین دوم بساز (`POST /admin/staff`) → authenticator خودش را
   ثبت کن → اولی را disable کن.

## ۶. چیزهایی که هست ولی روشن نیست

- **TON**: آداپتورش یک طرح ناتمام است (آدرسی را poll می‌کند که هیچ‌وقت به آن داده نمی‌شود،
  فقط توکن بومی، بدون تست). خاموش است و باید خاموش بماند.
- **Solana**: آداپتورش روی هر متد throw می‌کند.
- **کیف پول خودِ فروشنده روی همهٔ زنجیره‌ها** — از کامیت این خط به بعد. فروشنده تا ۱۰ آدرس
  از کیف پول‌های خودش را روی هر زنجیره (BSC، Ethereum، Polygon، TRON) ثبت می‌کند؛ هر فاکتور
  مبلغی کمی متفاوت می‌خواهد (۲۰.۰۵، ۲۰.۰۳، بعد ۲۰.۰۱۱) و همان مبلغ فاکتور را شناسایی می‌کند.
  یک فاکتور فعال روی یک کیف پول → هر مبلغی که برسد به آن نسبت داده می‌شود؛ دو فاکتور فعال →
  فقط مبلغ دقیق، وگرنه به صف ادمین می‌رود. **هیچ قراردادی از ما لازم نیست، گس نداریم، کارمزد
  شبکه به خریدار منتقل نمی‌شود، حداقل مبلغ ندارد.** کمیسیون به حساب فروشنده اقلام می‌شود
  (`accruedFeeBps`)، مثل TRON از اول.
- **قراردادهای Forwarder روی EVM** — مسیر دوم، در کنار مسیر بالا. برای فروشنده‌ای که کیف پول
  ثبت نکرده و آدرس تسویه داده: `node contracts/deploy.mjs --dry-run` اول، بعد
  `FORWARDER_FACTORIES` / `FORWARDER_IMPLEMENTATIONS` / `FEE_COLLECTORS`، یک کلید تسویه و
  موجودی گس با هشدار. اگر فروشنده روی یک زنجیره کیف پول داشته باشد، همان استفاده می‌شود و
  این مسیر آنجا لازم نیست.
- **حداقل مبلغ فاکتور** فقط روی فاکتورهای Forwarder (EVM با قرارداد) از گس می‌آید (روی BSC
  حدود ۶ دلار). فاکتوری که به کیف پول خودِ فروشنده می‌رود **روی هیچ زنجیره‌ای حداقل ندارد**.
  برای تست Forwarder با چند سنت، `MIN_INVOICE_FEE_RATIO` و `MIN_INVOICE_USD` را در `api.env`
  بگذار — `docs/GO-LIVE-fa.md` توضیح داده.
